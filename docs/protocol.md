# 逆向与重建协议

这份协议供复杂任务按需使用。执行时按目标跳过无关步骤；每项分析最终都服务新任务或用户提出的解释问题。

## 1. 建立素材账

每个来源记录 `source_id、标题/路径、作者或机构、日期或版本、语言、文类、载体、目标读者、取得方式、可用范围、是否完整、访问深度`。对不同版本保留时间关系。抽样需要覆盖典型篇、反例篇和不同载体；若只能看到节选，结论止于节选。网页引用和作者自述分别标记，不能当同一种证据。

为新写作任务另建事实账：`fact_id、原材料位置、准确表述、允许的推断、不可推断之处、是否过时`。另建必要的**关系账**：`两个片段、关系类型（同一事件/因果/仅联想/未知/冲突）、支持该关系的来源、读者可能误推的关系`。参考作品中的素材留在参考账，除非用户明确要讨论该作品本身。

关系核验先从现稿记录读者可辨认的实体和连接，再看来源是否支持；别用内部事实账替现稿消除歧义。事件按材料支持的局部先后比较，表达顺序与发生顺序分开，不能将缺少顺序证据等同于确定的次序。具体判法与核验失败状态见[关系核验](relation-checks.md)。

对口述、照片和回忆材料，分别标出事件发生时、讲述或观看时、编辑写作时；主观判断要有说话人及所指对象。照片证明画面所见，不自动证明店名、活动场次、人物关系、拍摄动机或拍摄当天的完整过程。若写“当时想、感到、性格如何、身体怎样”，逐句记 `所指对象／谁的判断／当时还是今天回望／依据／文学联想边界`；来源只有照片时不能把编辑推想写成当时心理。允许现在的比喻，但要使读者读得出视角。多张照片按主题排列时，跨图的“先、然后、再往后”需核是否真有时间顺序及同日关系。两个真实句子相邻也可能生成错误暗示，最终需按段落读一遍。[相关证据说明](evidence-notes.md)表明，已有关系账能抓到一处跨图风险，却漏过若干动机和感受补写；这一步不能省。

## 2. 复用成稿主线中的结构与动作

按[成文与修订](writing.md)完成读者任务、材料选择、参考动作、段落及独立阅读；复杂任务在已有记录上补信息，不再另做一份逆向提纲与作用图。判断主线时连看任务、篇章、段落和语言：一句短句可能由版面、题材或读者造成，不能单独认作作者习惯。

确需保存可复用机制时，集中记一条：`源文位置和可见动作／作用假设与竞争解释／适用条件和反例／新材料依据／新稿实际落点及失败信号`。迁移细则见[迁移指南](transfer.md)，思考方法的证据筛选见[思维提炼](thinking-patterns.md)。同一机制只保留这一份；普通新稿不必建卡。

需要较多外部资料时，按[长文研究](research.md)把必要问题、取得的证据、章节职责和实际输入接起来。分段保留已写内容与未兑现的承诺，拟写提纲不当事实源。新题不适用源文的问题时换结构，材料不足时补查或收窄断言。

稿内若有逐字引用、可复制模板、示例提示词、命令或公式，识别各自用途与允许改动的范围。引用核出处和呈现身份；模板核必要字段与待填条件；命令、参数和公式核任务要求保留的形式与含义。周围正文的语气调整不自动改变这些材料。用户要求修改内嵌对象时，按获准范围改并回查相关说明；格式正确与实际可用分别判断，未运行不声称已经成功。来源与取舍见[声音画像与内嵌材料](evidence-notes.md#声音画像与内嵌材料)。

解释类任务另设**解释增量检查**：对想补进或保留的解释句，记录它回应的潜在读者问题及前文锚点；先核与上下文是否相关、逻辑和事实是否成立、是否只是重复；再判断它对目标读者增加了什么理解。若问题已被前文答完，句子仍可能承担必要转场或记忆提醒，但须结合篇章检查，不能靠“读起来像总结”直接保留。把已隐含关系说清与新添事实分开标记。此检查来自[相关证据说明](evidence-notes.md)和 P001 反馈，属于**解释文类的候选机制**，尚无跨文类效果结论。

## 3. 诊断与反馈

评价分开：事实/设定一致性、**事实间关系**、读者任务、结构与论证、指定的风格属性、自然度和原创性。解释文类还要把**处理起来是否顺畅、读者自觉理解、实际能否回答问题**分开。源文问答可以检查新稿是否保留关键事实；问答未覆盖的事实和来源关系仍需逐条核对。若读者反馈“难懂”，追问是在前提、关系、例子还是语言处断裂，然后只改相关层。修订前记录原版与授权范围；改后回读原问题及相邻段落，检查是否引入新的缺口。

若要测真实理解，问题先由来源事实和读者任务制定，不从某一候选稿倒推；每题核唯一答案、来源支持及不看文章能否猜中。对每份候选先独立判“稿件能否支持回答”，然后给首次阅读的读者作答，并允许“本文无法回答”。读者选择正确、选择无法回答、误读关键句或误用文中别处，分别记录。只在稿里找到对应句不等于读者已理解；答对几道题也不等于理解全文。同一读者再看同题新稿时，先前暴露需标明，不能算独立首次阅读。此处参考 [K05 阅读理解评价](https://aclanthology.org/2024.tacl-1.24/)与 [L04 STARC](https://aclanthology.org/2020.acl-main.507/)，应用边界见[相关证据说明](evidence-notes.md)。

多版修订先对齐**段落作用→句子主张→必要片段**，再标删、添、替换、移动和推定意图。字词差异只是定位线索：同一句可能同时改事实力度、解释顺序和语气，也可能只是换了同义词。每个实质改动要记 `旧版锚点／新版锚点／针对哪条反馈或事实／编辑者意图／实际保留和失去的信息／待读者验证的问题`。从成稿能观察改了什么，不能反推出原作者当时的真实心理；编辑者的理由也不能代替读者效果。此处参考 [arXivEdits 的多层版本对齐与修改意图](https://aclanthology.org/2022.emnlp-main.641/)；[相关证据说明](evidence-notes.md)展示了同一反馈下的遗留风险。

### 将反馈落实为修改

普通改稿按需要走以下步骤，无需让读者填写表格：

1. **解释反馈的对象。** 保留原话和当时所看的版本，区分明确请求、问题报告、稿件选择和编辑者推测。只有“A更自然”时记录自然度选择；没有理由就留空，不补出“喜欢短句”等原因，也不因此重写获选稿。
2. **定位需要变化的内容。** 先回到现稿找相关信息、关系或表达；已有多版时，再对照实际差异，判断问题为何仍存在。一个反馈可对应多处改动，一处也可回应多个反馈；关键词相关不等于已经回应。编辑意图是对这次动作的说明，不能从事后标签推成用户心理。
3. **用已有材料选择动作。** 可以补清条件、调整顺序、删除重复，或依据材料解释某个前提为何不成立；缺实验、数字或当事人经历时，先按授权补查或保留缺口。内部待补项不伪装成完成的正文。给用户的答复可以解释处理方式，稿件本身应在上下文中完成任务，避免只把反馈改写成一句承诺。
4. **从已采纳版本继续。** 应用获准且实际采用的改动，回读相邻段落及原有约束。互相依赖的改动一起检查，例如删定义后，后文术语是否仍可理解。被明确拒绝的同一提案不原样重推；近似提案须回到拒绝对象和理由判断，不能仅靠字符串不同就当新方案。没有理由时不扩成永久禁词；材料或任务改变后可重新判断。

这组步骤综合[ARIES](https://arxiv.org/html/2306.12587v2)的反馈—编辑对齐、[IteraTeR](https://aclanthology.org/2022.acl-long.250/)的修改意图与[R3](https://aclanthology.org/2022.in2writing-1.14/)的交互状态机制，并加入本地编辑判断。它是待验证的执行说明，不是已复现的效果。只核原问题是否真正改善、必要内容是否仍在；找不到完成依据时保留未回应或待核。

归档时保存实际败例、已修改规则和仍未知的条件。单次成功不能证明通用有效；重复失败则优先修改机制卡，而非增加更多同义风格描述。
