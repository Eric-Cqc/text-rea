# Mac 环境重建现场核对卡

## 先确认适用范围

仅在已获授权的 Mac 环境迁移、恢复或重建中使用，包括应用重建包的 AI 配置。打开目录、日常开发、维护指令和只读盘点不触发本流程。一般安全与授权要求仍然适用。逐项检查，已满足的项目跳过。

## 全程保护数据与现有状态

禁止读取、索要、输出、复制、记录或提交秘密，包括密码、令牌、Cookie、钥匙串数据、`.env` 值和私钥。跳过含秘密文件的自动备份与替换；采用官方交互登录，报告必要的手动步骤。

不复制数据库物理目录或 `Docker.raw`；只使用获授权且符合敏感数据限制的逻辑导出。

核验和 dry-run 期间，Git 保持只读，不做 `fetch`、`pull`、`push`、`checkout`、`reset` 或 `clean`。保留已有改动；Git 提交不能备份未跟踪文件或机器状态。

## 按顺序检查与实施

**1．定位输入。** 明确已授权的重建包和目标路径。读取该包的 `START_HERE.md`、`AUTONOMOUS_REBUILD_PLAN.md`，以及 `machine-state.json` 的非秘密字段。包内相对路径从该包目录解析。

**2．核对校验清单。** 执行包内代码前，按指定清单核验源文件。前提缺失或校验不符时，停止依赖它的重建操作；安全的独立检查可以继续。校验一致仅证明与清单相符，本身不能证明来源真实。

**3．确认目标机。** 检测硬件和进程架构，考虑转译进程。查实运行时与 MCP 可执行文件的位置，逐一核对待替换路径；路径以目标机为准，不照搬旧绝对路径。

**4．检查脚本，再审阅 dry-run。** 先读 `scripts/rebuild-with-codex.sh` 及相关调用代码，确认 dry-run 不修改目标、不泄露秘密、不超出已授权网络访问。从已核验的重建包目录运行：

```text
scripts/rebuild-with-codex.sh --dry-run --apply-ai-configs
```

正式重建前审阅拟议影响。仅凭标志名称不能判断操作安全。

**5．核验可恢复备份。** 修改现有目标前，为受影响内容建立并核验可恢复备份，记录位置和恢复方法。没有安全备份，就停止该项修改。备份不扩大删除、卸载、清理、重置或覆盖的授权。

**6．实施、核验并交接。** 只实施已授权、经审阅的 dry-run 所覆盖的变更；受影响的现有内容须有已核验备份。核验实际行为。步骤失败后，停止依赖步骤，继续安全独立工作。

逐步报告 **completed、skipped、warning、failed、manual**，附简要核验证据及适用的备份位置或下一步。命令退出成功不能代替结果核验。
