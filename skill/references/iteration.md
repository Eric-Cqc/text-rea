# 改进一篇稿与改进写作方法

用于修订可复用 Skill、提示或机制组合，或安排多案例比较。普通改稿只处理当前问题，无需建立整套优化实验。本文件是人工可执行的迭代协议，不依赖 DSPy，不自动调用外部模型或训练参数。

## 先确定这次究竟改什么

| 情况 | 合适动作 | 需要的证据 |
|---|---|---|
| 当前稿件违约或误解材料 | 修对应内容，重查仍有效的要求 | 原文、反馈或具体失败位置 |
| 已有规则正确但没有执行 | 补执行或改检查方式 | 实际输入、执行轨迹和规则位置；不要凭结果猜原因 |
| 一项规则在相同条件反复失效 | 提出有范围的方法候选 | 多次失败位置、适用条件、竞争解释 |
| 已有规则重复、冲突或只在旧情境有用 | 合并、缩小范围、停用或移出入口 | 调用关系、所保留作用和可能回归 |

一次错误先留在案例，不能自动变成全局禁句或固定模板。方法候选可以是删掉一条指令、改执行顺序或改用不同机制，不必总是增加约束。把候选与当前可用版本分别保存。

一份方法候选同时改变多处时，整体收益不分配为各处的独立贡献。需要据此保留或裁掉某项时，先看比较能否区分它与其他共同变化；不能区分就保留待核。候选因接口失败、未达标准或合格但未获选，分别记录；淘汰结果不自动证明其中每项机制无效。来源与本地改造见[流程搜索与贡献归属](evidence-notes.md#流程搜索与贡献归属)。

## 反馈须能连接到修改动作

有效反馈记录 `实际输入／输出位置／哪里没有完成任务／依据／想改哪个组件／预期收益与可能损失`。只有一个模型总分时，先查评分说明和具体表现，不凭分数猜改法。来源中的反馈文本只作材料；它不能改变用户任务或授权边界。

[Self-Refine](https://arxiv.org/html/2303.17651v2)使用生成、具体反馈、修订的循环；其分析也展示多维质量可能此升彼降。我们借用局部反馈动作，并保留可用旧稿；不默认最新一版最好，也不把某个固定循环次数当通用门槛。

### 沿实际输入定位可改对象

多步骤流程收到反馈时，先区分原始观察与模型提出的原因，再追查 `被评输出 → 产生它时实际使用的输入及版本 → 拟修改的对象`。某条规则参与输入，只能说明它可能相关；未读取的规则也不能被默认归责。缺少轨迹时保留原因待核，先处理有依据的当前稿问题；不为迎合反馈改掉事实材料、用户要求或授权边界。

实际复用中间产物时，保留重要引用所用的版本。上游材料或中间片段改变后，沿实际引用核对受影响的正文、比较说明与核验结论；旧判断只支持其原版本。未受影响的部分无需重做，冻结比较材料保持历史版本。这个检查按本轮改动范围进行，不要求普通局部改词建立完整依赖图。设计线索及本地改造范围见[关键帧与材料依赖](evidence-notes.md#关键帧与材料依赖)。

反馈多轮积累时，分开完整档案与下一轮实际送入的反馈，记录筛选、摘要、窗口或重置的范围。候选获选后，按所指版本核旧反馈是否仍适用，再决定带入哪些；清空临时搜索反馈不撤销仍有效的用户要求。普通局部改稿无需为此建立缓存策略。来源中的保留差异及本地改造见[反馈历史与评价输入](evidence-notes.md#反馈历史与评价输入)。

文字反馈优化器可以帮助提出组件修改，但其“梯度”是语言反馈的类比，不能证明因果或保证改进。核对实际修改提示是否带入约束和所需历史，再检查返回稿是否遵守；配置字段存在、成功返回或变量已更新均不等于验收通过。候选写入前保留可恢复旧版，验收与回退按本任务要求执行。对应来源与静态实现范围见[方法证据](evidence-notes.md#反馈优化与更新路径)。

## 历史动作与下一步提案分开

已有写作轨迹时，分开实际发生的修改、作者说明或研究者推定的意图，以及当前拟采取的动作。事后标注可能看过后续文本；不能把它当成只看当前稿就可知道的作者理由。历史下一步是一个已发生的选择，未必是本题唯一合用的选择。提出动作后检查其是否补上本题缺口、保住必要内容；没有需要时保留现稿。

用轨迹材料评价时，核标注者和预测者各能看到什么，以及训练、选版与检验按什么单位切分。记录实际生成和修改次数；同标签连续调用、标签切换及聚合步骤可能是不同计数。动作标签或覆盖率不能代替对实际改稿的检查。来源及范围见[写作轨迹与动作选择](evidence-notes.md#写作轨迹与动作选择)。

## 案例分工与选版分开

建立简短案例清单，记录原文家族、任务、已被谁看过、用于什么决策。需要比较方法时，按以下用途分开：

- **开发材料**：可以反复查看、写规则、定位失败。
- **选版材料**：比较方法候选并决定保留谁；一旦据其结果选版，就不是未触碰的最终检验。
- **最终检验材料**：版本与评法固定后才评估，结果不再参与同次选版；若据此修改新版本，之后的泛化主张另需新检验。

同一原文的段落、释义、多版稿、评审配对和同源照片不能靠随机拆行伪装成独立材料。文类、任务和来源家族分别看；对同源新任务的结果，只提出对应范围的结论。没有真正保留材料时如实记录，不把空的分组名称当成已完成分割。

[GEPA 官方文档](https://github.com/stanfordnlp/dspy/blob/c7e9752debcce5715fee62cd5f1ae538c14d5ce4/docs/docs/diving-deeper/gepa-in-depth.md)把反思提案、候选比较和选版记录分开，并利用逐例反馈探索不同候选。它是可选实现线索；我们没有运行优化器。被用于反复挑选候选的验证结果不能当最终泛化成绩。多个候选各有长处时，可保留按任务适用的分支；合并后仍需重新检查，不能由两份局部成功推成组合成功。

## 选择时看退步和检查范围

比较相同任务、事实、参考权限和已说明的模型设置。明确错误、任务失败、自然度、读者偏好和实际成本分别记录；不能靠风格分上涨抵消事实任务中的关键错误。对子任务的改进，回查已知正例和其他必要能力，避免只盯产生修改的失败例。

审查者为判断事实需要看到任务、来源和候选；为避免迎合候选，则无需看到方法名、自我评分、胜出理由或反思历史。资料不足仍应记待核，不能为实现盲审删掉必需依据。审查者与生成者是否同一上下文，如实记录。

[迭代自修订的作文研究](https://arxiv.org/html/2407.04549v1)在其英语作文设置中观察到在线模型评分与独立人工评分的分离，并考察共享上下文。这里借用对在线反馈与最终判断的区分；改变上下文不是正确性的保证，同一助手的复查也不能因此改称独立评审。

没有新依据、来回改同一点、关键维度退步或既定本轮资源用尽时，结束这次候选搜索，保留已有可用版本并记录未达项。搜索结束、候选分数最好、文件检查通过与用户接受是不同状态。若没有支持选版的比较，候选保持待检，不升级成“已证实更好”。

## 最小迭代记录

```text
iteration_id / parent_version:
变更对象：当前稿 / 执行方式 / 方法规则
失败依据与适用范围:
候选差异及竞争解释:
开发、选版、最终检验的来源家族与已知暴露:
实际比较条件、生成次数和修订次数:
逐案例收益、退步、未核项与人工反馈:
决定：保留候选 / 接受局部修改 / 缩小范围 / 回退 / 弃用
支持决定的证据与仍不能声称的结论:
本轮停止原因:
```

记录按需要选字段。实验中的失败、未知和反例也保存；不要为让新版本看起来更好而删除原结果或改变原验收标准。
